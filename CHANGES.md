# Add: .gitignore + git init instructions

Place `.gitignore` in the project root (same level as `package.json`).

## Initialize git

Run these from your project's root folder:

```bash
cd donfosters-dive-redesign   # or wherever your project folder is

# 1. Initialize the repo
git init

# 2. Stage everything (the .gitignore above makes sure node_modules,
#    .next, and env files are excluded automatically)
git add .

# 3. First commit
git commit -m "Initial commit: Don Foster's Dive Cayman site"

# 4. (Optional) set your identity if git asks for it
git config user.name "Your Name"
git config user.email "you@example.com"
```

## Connect it to GitHub (or GitLab/Bitbucket)

1. Create a new, **empty** repository on GitHub (don't initialize it with a
   README or .gitignore — you already have one).
2. Copy the remote URL it gives you, then:

```bash
git remote add origin https://github.com/your-username/your-repo-name.git
git branch -M main
git push -u origin main
```

After that, any future changes are just:

```bash
git add .
git commit -m "Describe what changed"
git push
```

## Why these specific ignores matter here

- `/node_modules` — huge, regenerated by `npm install`, never committed.
- `/.next/` — the build output; regenerated every `npm run build`/`npm run dev`.
- `.env`, `.env*.local` — if you ever add a `.env` file (API keys, booking
  system credentials, etc.), this keeps secrets out of git history.
- `next-env.d.ts` and `*.tsbuildinfo` — auto-generated by Next.js/TypeScript,
  safe to regenerate, not meant to be hand-edited or versioned.

If you already have a `public/images/` folder full of large photos (yours is
~28MB), that's fine to commit as-is for a project this size — just something
to keep in mind if the repo grows a lot larger down the line (at that point
tools like Git LFS become worth considering, but not necessary yet).
